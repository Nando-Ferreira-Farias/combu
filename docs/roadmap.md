# Roadmap

## Moving the logic into the extension

The registry started inside an application, with its logic split between SQL and Python. It moves into the extension one step at a time ([decision 0003](decisions/0003-sql-core.md)):

| Step | State |
|---|---|
| 1. The core's tables and functions as plain SQL | done (0.1.0) |
| 2. Packaged as a PostgreSQL extension, with dump-safe data tables | done (0.1.0) |
| 3. The catalog (entity types, hierarchies, rules, code lists) as data only, inserted by domain extensions | next |
| 4. Sync over staging tables as a SQL function: claims resolution, diff and apply, with a plan as result | |
| 5. `asof` views and type-check triggers generated by a SQL function from the catalog | |
| 6. Geography and an electrical system as domain extensions (`combu_geo`, `combu_power`) | |
| 7. combu-py takes over the data contract's file format (TSV folders) and the queries | |

## What the core must eventually answer

The first application analyses Latin American electricity markets: Chile, Colombia, Peru and Argentina first, other regions later. Its questions show where the core has to go. These are design drivers, not commitments:

| Question | What it needs from the core |
|---|---|
| "How has Chile's renewable capacity grown in the past years?" | What exists at each date, with its attributes and hierarchies, from several sources ranked by priority. **In place.** |
| "What are the main price drivers in Colombia and Peru?" | Time series of prices, demand, hydrology, fuel prices and generation by technology. They must line up in time across markets with different time zones, units and currencies, and aggregate along hierarchies at each instant. |
| "What price should Argentina expect next year if El Niño comes?" | Forecasts and scenarios as first-class data. That means the time a forecast was issued (its vintage) as well as the time it is about, scenario dimensions, and entities that belong to no country (a climate index such as ENSO). |
| Any of these, asked of an agent | A described catalog: what each entity type, hierarchy, metric and dataset means, in the database, so a client or an agent can discover what can be asked. |
